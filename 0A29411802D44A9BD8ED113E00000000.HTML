Funktionalität

Der Funktionsbaustein führt für die übergebenen Daten - wenn vorgesehen - eine Adressnormierung mit UNISERV durch. Fehler bei der postalischen Prüfung werden bei erlaubtem Dialog über ein Fenster zur Korrektur angeboten. Ansonsten wird eine Ausnahme ausgelöst.

Ist die Ziel-ID im Sendersystem bereits bekannt, wird im Referenzdatenbestand geprüft, ob für die Ziel-ID bereits eine GP-Nummer vergeben wurde. Ist dies nicht der Fall, wird - wenn vorgesehen - eine Dublettenprüfung mit UNISERV durchgeführt. Vorhandene Dubletten werden bei erlaubtem Dialog über ein Fenster zur Auswahl angeboten. Ansonsten wird eine Ausnahme ausgelöst.

Ist der Geschäftspartner noch nicht vorhanden, erfolgt anschließend der Aufruf der Dunklen Pflege (DI), bei der alle Prüfungen der GP-Anwendung durchgeführt werden. Bei fehlerfreiem Ablauf wir der Geschäftspartner angelegt. Liegen Fehler vor, werden bei erlaubtem Dialog alle Inputdaten über ein Dynpro zur Korrektur angeboten. Ansonsten wird eine Ausnahme ausgelöst.

Ist der Geschäftspartner bereits vorhanden, werden alle GP-Daten (Standardadresse mit zughöriger Kommunikation) mit den Imputdaten verglichen. Liegt mindestens bei einem Feld eine Abweichung vor, werden bei erlaubtem Dialog alle internen und externen Daten auf einem Dynpro zur Kontrolle und Übernahme angeboten. Ansonsten wird eine Ausnahme ausgelöst.

Für die neu vergebenene bzw. ermittelte GP-Nummer wird geprüft, ob es schon Einträge in Tabelle /VWK/SKS_DISTTAB gibt. Sind bereits mehrere Verteileinträge zu der Kombination Zielsystem und -rolle vorhanden, wird bei erlaubtem Dialog ein Dynpro zur Auswahl ausgegeben. Ansonsten wird eine Ausnahme ausgelöst.

Ist noch kein Verteileintrag vorhanden, wird dieser mit der Transaktion /VWK/SKS_ZVTE angelegt. Bei fehlerhaftem Ablauf wird eine Ausnahme ausgelöst.

Zuerst wird für jeden gespeicherten Satz eine Adressnormierung durch UNIPOST durchgeführt.Wenn die KREDIS-Kundennummer (Ziel-ID) nicht mitgegeben wurde (normaler Ablauf), erfolgt anschließend eine Dublettenprüfung über UNIMAIL.

Die Eingabefunktionalität wurde zudem um die Erfassung von E-Rechnung daten aus Leasis- und Kredis-Systemen erweitert.Die über die Eingabe verarbeitete Rolle ist zwar stets 'Kunde', die Funktionalität steht jedoch für alle Rollen zur Verfügung.Es wurde eine Prüfung implementiert, die sicherstellt, dass im Rahmen des Eingabeprozesses dem Geschäftspartner (BP) ausschließlich die Rolle 'Kunde' hinzugefügt werden kann.
